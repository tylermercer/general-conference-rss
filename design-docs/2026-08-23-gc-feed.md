# Spec: General Conference RSS Feed (Astro/Cloudflare starter)

## Goal

Add a build-time-generated RSS feed of General Conference talk links to a
site based on [astro-cloudflare-starter](https://github.com/tylermercer/astro-cloudflare-starter),
plus a root landing page explaining how to subscribe. Discoverable by
pasting the bare site URL into a reader (RSS autodiscovery). Items are
link + title only (audio enclosures stubbed for later — see §3). Talks
are released as a drip feed, evenly paced across the gap between
conferences.

## Decisions locked in

1. English only (`lang=eng`) for v1.
2. All talks included **except** Sustaining of Officers and the Church
   Auditing Department Report. Introduction and Closing Remarks *are*
   included (they're real talks, just short ones).
3. Conferences from **2026 onward**, and only once at least **one week**
   has passed since the conference weekend. As of now, that's April 2026
   only — October 2026 won't be eligible until ~Oct 11–12, 2026.
4. Landing page at the site **root** (`/`).
5. Drip feed: a talk's RSS `pubDate` is scheduled in advance, but the
   item is **withheld from the feed entirely** until that date arrives
   (build-time filter, not just a future-dated item sitting in the feed).
6. Talks are paced evenly across the **actual calendar gap** between
   "one week after conference A" and "the first day of conference B,"
   in **broadcast order** (Sat AM → Sat PM → Sun AM → Sun PM). Because
   the window for conference A ends exactly when conference B begins,
   consecutive conferences' pacing windows never overlap.
7. Audio: **stubbed out**. See §3.

## Background / constraints

- The Church's own RSS/podcast feeds have been broken for years; this
  replaces them with a self-hosted one.
- Talks live at predictable URLs:
  `/study/general-conference/{year}/{month}/{id}{slug}?lang=eng`
- No official API (confirmed — the Church has repeatedly declined to
  offer one; see their tech forum). Source of truth is the conference
  "Contents" page (e.g. `/study/general-conference/2026/04?lang=eng`),
  which lists every talk with title, speaker, and URL in one nav block.
- The starter already **rebuilds and redeploys daily via GitHub Actions
  cron** (15:00 UTC) plus on every push. Ride that existing pipeline
  rather than add a second scraper/cron/hosting setup — the feed is
  build output, same as any other page.
- Astro's static build mode fetches at build time in Node, so scraping
  happens during CI, not in the browser and not in a separate service.

## Architecture

### 1. Data fetching (build-time utility)

New file: `src/utils/fetchConferenceTalks.ts`

- Fetch the General Conference collection page. Extract all conference
  links matching `/study/general-conference/(\d{4})/(\d{2})`.
- Filter to `year >= 2026`.
- For each candidate conference, compute its weekend dates (see §2) and
  drop any where `today < conferenceEndDate + 7 days`.
- For each remaining eligible conference, fetch its contents page and
  parse talk links in broadcast order: `{ title, speaker, url,
  sessionSlug, conferenceYear, conferenceMonth }`. Exclude:
  - session-wrapper links (`*-session` slugs)
  - Sustaining of Officers (title match, e.g. "Sustaining of General
    Authorities...")
  - Church Auditing Department Report
- Export `getEligibleConferenceTalks()` returning talks from all
  eligible conferences, in conference order then broadcast order.
- Guard with try/catch; see §7 (Resilience).

### 2. Conference dates + pacing (build-time utility)

New file: `src/utils/conferenceSchedule.ts`

- `getConferenceWeekend(year, month)`: general conference is always the
  first full Sat/Sun weekend of April and October — compute the actual
  Saturday/Sunday calendar dates.
- `getNextConference(year, month)`: returns `{ year, month }` for the
  following conference (April → October same year; October → April next
  year).
- `schedulePubDates(talks)`: given all talks for one conference, in
  broadcast order:
  1. `windowStart = conferenceWeekend.sunday + 7 days`
  2. `windowEnd = getConferenceWeekend(nextConference).saturday`
  3. Divide `[windowStart, windowEnd)` into `talks.length` equal
     intervals; assign each talk the start of its interval as `pubDate`.
     (First talk's pubDate = windowStart, so it's immediately available
     once the conference clears the one-week mark.)
- This is fully deterministic given only the conference's own year/month
  — no persisted state needed, reproducible on every build, and talks
  never reorder between builds.

### 3. Audio enclosures — stub only (v1)

Do **not** implement real audio in this pass. There's no predictable
audio URL pattern (unlike talk pages); the MP3 link is only exposed via
a "Download" menu on each individual talk page, which would mean an
extra fetch per talk and DOM inspection whose exact shape isn't
confirmed. That's real scope for a follow-up spec.

For v1:

- Add an `enclosureUrl?: string` field to the talk data shape and to the
  RSS item builder in `rss.xml.ts`, wired to emit an `<enclosure>` tag
  *if* present — but leave it `undefined` for every talk.
- Leave a `// TODO(audio):` comment at the point where it would be
  populated, describing the per-talk-page fetch + parse that a future
  pass needs to add.
- This keeps the schema/route shape stable so adding real audio later
  is a data change, not a route rewrite.

### 4. RSS route

New file: `src/pages/rss.xml.ts`

- Use the official `@astrojs/rss` package (add to `package.json`).
- `export const GET: APIRoute = async ({ site }) => { ... }`:
  1. Call `getEligibleConferenceTalks()`.
  2. Call `schedulePubDates()` per conference.
  3. **Filter to `pubDate <= buildTime`** — this is what makes it a real
     drip feed rather than a future-dated list.
  4. Sort remaining items newest-first.
  5. Return `rss({ title, description, site, items })`, each item
     `{ title, link, pubDate, guid: link, enclosure: item.enclosureUrl
     ? { url: item.enclosureUrl, type: "audio/mpeg" } : undefined }`.
- Prerenders by default in the starter's static mode — generated once at
  build time, served as a static file.

### 5. RSS autodiscovery

Edit `src/layouts/Base.astro`:

```html
<link rel="alternate" type="application/rss+xml"
      title="General Conference Talks"
      href="/rss.xml" />
```

This is what makes "just paste the base URL" work — readers that
support autodiscovery (most do) find the feed from the homepage's
`<head>` without needing the `/rss.xml` path spelled out.

### 6. Landing page (root)

Edit `src/pages/index.astro` (this feed is the site's whole purpose, so
root is the landing page itself, not a separate route):

- Plain-language explainer: what the feed is, why it exists (Church's
  own feeds are broken), that it's link-only for now (no audio yet).
- Explain the drip-feed pacing in a sentence, so subscribers understand
  why they see one or two new items every few days rather than a wall of
  34 talks at once.
- Direct feed link (`/rss.xml`) plus copy-paste instructions for readers
  that don't autodiscover.
- Surface live build data for reassurance: count of talks released so
  far for the current conference, and the next scheduled release date/
  talk title (from `schedulePubDates()`, this is cheap to compute at
  build time even for items not yet in the feed).

### 7. Resilience

- Wrap fetch/parse in try/catch inside `fetchConferenceTalks.ts`.
- On failure, log a clear warning and return an empty list rather than
  throwing — the route still builds; the feed just doesn't gain new
  items until the next daily run.
- No cross-build fallback/caching — the existing daily cadence is the
  retry mechanism.

### 8. Build cadence

- Existing daily 15:00 UTC cron is sufficient given the drip-feed model
  — items are scheduled well in advance, so a same-day build always
  catches a newly-arrived pubDate.
- No special-cased conference-weekend cadence needed for v1, since raw
  talk availability speed no longer matters once pacing decouples
  release from posting time.

## File-level checklist

- `src/utils/fetchConferenceTalks.ts` — scrape + parse + eligibility
  filter + exclusion filter
- `src/utils/conferenceSchedule.ts` — weekend date calc, next-conference
  calc, pacing/pubDate assignment
- `src/pages/rss.xml.ts` — feed route (`@astrojs/rss`), drip-feed filter
- `src/pages/index.astro` — landing page content
- `src/layouts/Base.astro` — add autodiscovery `<link>`
- `package.json` — add `@astrojs/rss`; add an HTML parser (`cheerio`) if
  not doing this with raw regex
- `README.md` — document the feed, the pacing model, and the audio stub
  as a known follow-up

## Follow-up work (explicitly out of scope for v1)

- Real audio enclosures (see §3).
- Non-English feeds.
